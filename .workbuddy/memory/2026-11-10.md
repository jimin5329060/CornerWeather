## 抽屉选城市：修 PlaceFragment 点击回调（编译通过）

**背景**：`PlaceFragment` 同时被 `MainActivity`（首页）和 `WeatherActivity`（抽屉 `<fragment>`）复用，
原回调里写了 `findViewById<DrawerLayout>(R.id.drawerLayout)` —— Fragment 的 findViewById 只搜自己的
`fragment_place.xml`，DrawerLayout 属于 Activity 布局，编译期报错/运行期拿 null。

**改动**：
- `PlaceFragment.kt`：回调改为 `val weatherActivity = activity as? WeatherActivity`。
  - 是天气页 → `weatherActivity.findViewById<DrawerLayout>(R.id.drawerLayout)?.closeDrawer(GravityCompat.START)`
    再 `weatherActivity.updateWeather(lng, lat, name)`，不重复 startActivity。
  - 是首页 → 老逻辑 startActivity + `activity?.finish()`。
  - `savePlace` 提到分支外统一调用。
- `WeatherActivity.kt`：新增 `updateWeather(lng, lat, placeName)`，改 viewModel 三个字段 + 复用
  `refreshWeather()`；**坐标相同直接 return**，省掉一次配额（防 429）。
  标题不在此处直接 setText，交给 `showWeatherInfo` 统一刷，避免 `R.id.placeName` 在
  Activity / RecyclerView item 里同名导致的误取。
- `PlaceFragment.kt`：`isPlaceSaved()` 自动跳转加了 `activity is MainActivity` 前置判断
  （用户自己加的），否则天气页抽屉里的 Fragment 会再 startActivity，造成 Activity 连环叠加 +
  每层 2 个请求 —— 这是 429 的重要来源。

## 429 结论（已用 curl 验证 token 正常）

单发 `realtime` 接口 200 OK，说明不是 token/额度废掉，是 App 端 1 秒内并发。三个来源：
1. 搜索框 `addTextChangedListener` 无防抖，每敲一个字一次请求（未改，待办）。
2. 从天气页返回 → Fragment 重建 → 自动跳转 → 又一组请求（已用 `MainActivity` 判断消除）。
3. `await()` 没接 `invokeOnCancellation { call.cancel() }`，switchMap 切走后请求仍在跑、配额照扣（未改）。

**待办**：搜索防抖 400ms + 最少 2 字符；`SunnyWeatherNetwork.await()` 加全局 Mutex + 1.2s 最小间隔闸门。

## 生成 App 图标（未写入项目资源，交给用户自己装配）

`generated-images/` 下产出：`app_icon.png`（1024 成品，深蓝渐变 + 白云 + 右上金色太阳）、
`app_icon_round.png`、`app_icon_foreground.png`（透明前景），以及 `icon-assets/` 整套可直接覆盖的资源：
5 个密度的 `ic_launcher.webp` / `ic_launcher_round.webp`、`mipmap-xxxhdpi/ic_launcher_fg.png`(432×432)、
`drawable/ic_launcher_background.xml`(渐变 shape)、`mipmap-anydpi-v26/` 两个 adaptive XML。

处理要点：ImageGen 出的是**不透明黑底 + 右下角「AI生成 WORKBUDDY」水印**，
用 Pillow 按 `C = a*F`（a = max(rgb)/255 再做 0.45 gamma）反解出透明前景，
并抹掉 (890,950) 之后的水印区域。环境原本没有 Pillow，已 `pip install pillow`。

**关键坑**：项目有 `mipmap-anydpi-v26/ic_launcher.xml`，targetSdk 35 的机器只看它，
只替换 legacy webp 桌面图标不会变；且替换时必须覆盖同名 .webp，新增 .png 会 duplicate resource。
